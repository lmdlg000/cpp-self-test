## 1. 题目背景

快递驿站按包裹重量计费：一单可能有多件包裹，程序要连续处理多单，逐单报出总运费、件数和最重那件包裹的运费。

## 3. 必做接口

```cpp
int shippingFee(int grams);   // 原型：签名固定，不得改名、不得增删参数、不得改返回类型
```

- 参数 `grams`：单件包裹重量（克）。**甲方保证调用时 `grams > 0`**；非法重量由 `main` 先拦截，不调用本函数。
- 返回：该件包裹的运费（整数元），规则见第 6 节。
- **调用关系**：`main` 对**每一个合法**重量 `w` 调用一次 `shippingFee(w)`，用返回值累加本单总运费、增加件数，并据此记录最重件的运费；`shippingFee` 只做一次纯计算，**不读输入、不输出任何东西**。函数定义放在 `main` 之后时，必须在 `main` 之前写出上面的原型。

## 4. 输入格式

- 输入是**空白分隔的整数 token**，不要依赖换行位置（README 第 2 节第 2 条）。
- 第 1 个整数 `R`（`1 <= R <= 1000`）：单数。
- 随后 `R` 单，每单：若干个整数重量（克），以 **`-1`** 结束本单。件数不定，可能为 0。
- `-1` 只表示"本单结束"，**不是**包裹重量，不参与计费；空单就是读完 `-1` 之前没有任何重量。
- 重量非法规则：`w <= 0` 或 `w > 20000`（且 `w != -1`）→ 由 `main` 用 `cerr` 报告后跳过（见第 6 节）。

## 5. 输出格式

每单输出一行，三个整数，用**一个空格**分隔：

```text
总运费 件数 最重件运费
```

- `总运费`：本单所有有效包裹运费之和。
- `件数`：本单有效包裹的件数（不含 `-1`，不含被 `cerr` 跳过的非法重量）。
- `最重件运费`：本单**最重的那件有效包裹**的运费；空单输出 `0 0 0`。
- 行末不要多余空格，末尾不要多余空行，不要输出任何提示语（README 第 2 节第 3 条）。

## 6. 计算规则与约束

单件运费 `shippingFee(grams)`（`grams > 0`，单位克，全部用 `int` 计算）：

| 重量 `grams` | 单件运费 |
| --- | --- |
| `grams <= 1000` | 8 |
| `grams > 1000` | `8 + 3 * extra`，其中 `extra` 为超出 1000 g 的部分按每 500 g 计一段、**不足 500 g 按 500 g 计** |
| 任意 | 算出来超过 50 的，取 50（封顶） |

- 超出部分向上取整**必须用整数运算**完成，题面给出等价写法：

  ```cpp
  int extra = (grams - 1000 + 499) / 500;   // grams > 1000 时
  ```

  不要用 `ceil()`、不要用 `/ 500.0` 等浮点做法（本题就是练整数向上取整）。
- 注意分支顺序：`grams <= 1000` 时**不要**计算 `extra`（会得到 0 或负数），直接返回 8。
- 封顶要在算完 `8 + 3 * extra` 之后判断：`if (fee > 50) fee = 50;`。
- **非法重量**（`w <= 0` 或 `w > 20000`，且不是 `-1`）：执行

  ```cpp
  cerr << "invalid: " << w << endl;
  ```

  然后 `continue`。非法重量**不计入件数、不计运费**，`stdout` 不受影响（README 第 4 节 R2）。
- `-1` 在任何情况下都只作本单结束标记，**绝不**当成非法重量报错，也绝不计费。
- "最重件运费"按本单**重量最大**的那件包裹的运费计算。由于本题运费随重量**单调不降**，它正好等于本单单件运费的最大值；但仍建议用 `maxW` 记录最重重量、用 `maxFee` 记录对应运费，空单两者保持 0。
- 本题不需要求绝对值，也不要引入 `abs()` 之类与计费无关的函数。
- 只用 `cin` / `cout` / `cerr`；只许课件头文件（`<iostream>` 足够），不要 `<bits/stdc++.h>`。
- 禁用 `rand()` / `srand()` / `time()`（README 第 3 节），本题没有随机成分。
- 禁用 STL 容器、`std::string`、`auto`、范围 `for`、`lambda`、`template`（README 第 3 节）。
- 本题**不要用数组**：件数不定，边读边算即可。

## 7. 样例

**【样例 1 输入】**

```text
4
1000 1001 1500 1501 -1
20000 -1
-1
5 3000 12000 -1
```

**【样例 1 输出】**（stdout）

```text
44 4 14
50 1 50
0 0 0
78 3 50
```

**【样例 1 诊断】**（stderr，评测忽略）：无输出。

**【说明】**

- 第 1 单覆盖首重边界：`1000` 在首重内 → 8；`1001` 超出 1 g，按 500 g 一段 → `extra = 1` → 11；`1500` 超出正好 500 g → `extra = 1` → 11；`1501` 超出 501 g，按 2 段 → `extra = 2` → 14。总运费 `44`，4 件，最重件 `1501` 的运费 `14`。
- 第 2 单 `20000`：`extra = (19000 + 499) / 500 = 38`，`8 + 3 * 38 = 122`，封顶为 `50`。单件单输出 `50 1 50`。
- 第 3 单是空单（读完就是 `-1`）→ `0 0 0`。
- 第 4 单：`5` → 8；`3000` 超出 2000 g，`extra = 4` → 20；`12000` 超出 11000 g，`extra = 22`，`8 + 66 = 74` → 封顶 `50`。总运费 `78`，3 件，最重件运费 `50`。

**【样例 2 输入】**

```text
3
7500 7501 8001 -1
0 -5 20001 25000 -1
123 999 -1
```

**【样例 2 输出】**（stdout）

```text
147 3 50
0 0 0
16 2 8
```

**【样例 2 诊断】**（stderr，评测忽略）

```text
invalid: 0
invalid: -5
invalid: 20001
invalid: 25000
```

**【说明】**

- 第 1 单卡在封顶边界：`7500` → `extra = 13` → 47；`7501` → `extra = 14` → 恰好 `50`；`8001` → `extra = 15`，本应 53，被封顶成 `50`。总运费 `147`。
- 第 2 单四个重量全部非法（`0`、`-5`、`20001`、`25000`）→ 跳过、逐条打 `stderr`，本单输出 `0 0 0`。
- 第 3 单 `123` 与 `999` 都在首重内，各 8 元，总运费 `16`、2 件、最重件运费 `8`。

**【样例 3 输入】**

```text
3
1 -1
4000 -1
1001 -1
```

**【样例 3 输出】**（stdout）

```text
8 1 8
26 1 26
11 1 11
```

**【样例 3 诊断】**（stderr，评测忽略）：无输出。

**【说明】**

- 三个单件单，覆盖最小重量 `1`、中间重量 `4000`、首重边界外 1 g 的 `1001`。
- `4000` 超出 3000 g，`extra = (3000 + 499) / 500 = 6` → `8 + 18 = 26`。
- 单件单的"最重件运费"就是这一件的运费。

## 8. 健壮性要求

本题额外要求（通用条目见 README 第 4 节；R9 是多文件题的要求，本题不涉及）：

- **R1**：`R` 单数据在一次运行内全部处理完，单与单之间互不影响；同一输入重复运行两次，`stdout` 必须完全一致。
- **R2**：非法重量只走 `cerr` + `continue`，不得写进 `stdout`，不得影响件数与运费。
- **R3**：必须正确处理空单（0 件）、单件单、全非法单、全非法后的空单，以及重量边界 `1`、`1000`、`1001`、`7500`、`7501`、`20000`。
- **R8**：三整数的顺序、空格、换行不得改动。
- 大单（重量多、`R = 1000`）必须能跑完；总运费用 `int` 足够（单件封顶 50）。

**甲方保证**：

- `1 <= R <= 1000`；每单以 `-1` 结束；输入 token 都是整数，不会被读坏；
- 在调用 `shippingFee` 时其参数满足 `1 <= grams <= 20000`。

**甲方不保证**（必须自己防守）：输入中的重量可能非法（`w <= 0` 或 `w > 20000`）；某单可能为空；某单可能全部非法。

## 10. 常见错误

- 用 `/ 500` 直接截断而不是向上取整：`1001` 会被算成 8 元（正确是 11 元）。
- 对 `grams <= 1000` 也计算 `extra`，得到 0 或负数后加进运费。
- 忘记封顶判断，`20000` 算出 122 元。
- 把 `-1` 当成非法重量报 `cerr`，或读到 `-1` 后没有 `break`、继续计费。
- 非法重量仍被计入件数或运费。
- 空单时 `maxFee` 用了未初始化值，输出不是 `0 0 0`。
- 用数组把所有重量存起来再算：本题不需要，件数不定，容易越界（第 3 周 *Array out of bound*）。
- 用浮点除法或 `ceil()` 算段数（题面要求整数运算，避免多余的精度问题）。
- 每处理新一单时忘记把 `total / cnt / maxW / maxFee` 清零（第 1 周变量初始化）。
- `shippingFee` 漏写原型、原型与定义参数不一致（第 3 周 *Error: Parameters not match*）或某条路径漏 `return`（*Not all paths returned*）。
- 诊断信息打到 `cout`，或输出中文提示、多余空格、多余空行（README 第 2 节第 3、5 条）。
