# P9 · 机器人任务调度（贪心排序）

> 难度：★★★　·　对应课件：第 1~2 周（整数与溢出）、第 10 周（STL 容器与算法：`vector`、`sort`、自定义比较）　·　构建：单文件 OJ（README 第 1.1 节）　·　提交文件：`P9.cpp`
>
> 通用约定（评测命令、输入/输出格式、禁用项、健壮性 R1~R9、评分）见 [README](README.md)；本文只写本题的额外要求。

## 1. 题目背景

一个机器人要连着干 `N` 个活。第 `i` 个活有个门槛 `a_i`：**当前电量必须 ≥ `a_i`** 才能开工；干完之后电量会掉 `b_i`（题面保证 `a_i ≥ b_i`，所以开工那一刻一定付得起）。电量只会掉不会涨，初始电量由你决定，但必须**足够撑到最后一个活干完**（每开工前的门槛都要满足）。

请回答两件事：**初始电量最少要多少**，以及**按什么顺序干**最省。

**与课件示例的区别**：课件第 10 周的 `sort` 例子只是"读一堆整数、排序、打印"；本题要求**自己定义排序键、写比较函数**，而且排序的目的是"让另一个量（所需初始电量）最小"——排序不是终点，是为了贪心。与 P1 的快递计费相比，这里没有浮点、没有取整，全是整数与累加，重点是"排序键怎么选"和"`long long` 别省"。

## 3. 必做接口

本题**不给定 `main`**：请提交一个完整程序（建议命名 `P9.cpp`），自己写输入解析、排序、输出。要求：

- 用 `#include <vector>`、`#include <algorithm>`，把任务放进 `std::vector`，用 `std::sort` 配一个**自定义比较函数**排序（不要用冒泡/选择排序硬排，本题考的就是 STL 算法）；
- 任务用 `struct`（或 `class`）表示，至少存 `a`、`b`、原始编号 `idx`；
- 电量累加一律用 `long long`。

> 判定不看你怎么写，只看输出；但"是否用了 STL 容器与算法"计入规范分（20 分），手写排序会被扣分。

## 4. 输入格式

第一行 `q`（`1 ≤ q ≤ 20`，数据组数）。

随后每组：

```text
N
a1 b1
a2 b2
...
aN bN
```

其中 `1 ≤ N ≤ 1000`，`1 ≤ b_i ≤ a_i ≤ 10^9`。token 之间用任意空白分隔（行数不必严格对应，见 README 第 2 节第 2 条）。

## 5. 输出格式

每组输出**两行**：

1. 最小初始电量（一个整数）；
2. 执行顺序：`N` 个任务编号（**1 起**），空格分隔，行末不要多余空格。

顺序的算法见第 6 节；同一组数据只有**一种**合法输出。

## 6. 计算规则与约束

1. **约定**：任务编号就是输入顺序（第 `i` 行是任务 `i`）。记排序后的执行顺序为 `p1, p2, …, pN`，记 `pre_k = b_{p1} + … + b_{pk}`（`pre_0 = 0`，已经消耗掉的电量）。要在第 `k` 个任务开工，必须满足

   ```text
   初始电量 E - pre_{k-1} >= a_{pk}
   ```

   所以这个顺序所需的最小初始电量是

   ```text
   E(p) = max over k = 1..N of ( a_{pk} + pre_{k-1} )
   ```

2. **最优顺序的唯一写法（本题规定）**：令 `key_i = a_i - b_i`，按

   - `key` **从大到小**；
   - `key` 相同时按**输入编号从小到大**

   排列。这就是第 2 行要输出的顺序。

3. **为什么这样最省（结论）**：交换论证——若相邻两个任务 `x`、`y` 满足 `key_x < key_y` 却排在 `x` 前，把这两个交换不会让 `E` 变大（`E` 只可能不变或变小）；反复交换直到 `key` 降序，`E` 只会更好。所以按 `key` 降序的顺序一定是最优顺序之一；`key` 相同时两种排法 `E` 完全一样，题面固定取"编号小的在前"。

4. **E 的计算**：按上面的顺序扫一遍，维护 `pre`（已消耗电量，初值 0）与 `best`（初值 0）；对每个任务：`best = max(best, a + pre)`，然后 `pre += b`。最后输出 `best`。

5. **溢出**：`a_i`、`b_i ≤ 10^9`、`N ≤ 1000`，`pre` 最大到 `10^12`，`a + pre` 也在这个量级——**`int` 会溢出，必须 `long long`**（第 1 周 *integer overflow*）。

6. **比较函数必须是严格弱序**：`cmp(x, y)` 返回"`x` 是否应排在 `y` 前面"；不要写成 `<=`，也不要让 `cmp(x, x)` 返回 `true`（`std::sort` 会越界/崩溃，见第 10 节常见错误）。

7. **允许使用**（第 10 周 STL 内容）：`<vector>`、`<algorithm>`、`<string>`、`std::sort`、`std::max` 等；`std::pair` / `std::tuple` 也可以。**仍然禁止**：`rand` / `srand` / `time`（必须确定性）；`<bits/stdc++.h>`。

## 7. 样例

**【样例 1 输入】**

```text
4
2
10 5
12 2
2
10 5
8 3
3
100 95
5 5
7 3
1
1000000000 1000000000
```

**【样例 1 输出】**（stdout）

```text
12
2 1
13
1 2
103
1 3 2
1000000000
1
```

**【样例 1 诊断】**（stderr，评测忽略）：无输出

**【说明】**

- **第 1 组**：`key` 分别是 `5` 和 `10`，任务 2 先做：`E = max(12, 10 + 2) = 12`。反过来的顺序要 `max(10, 12 + 5) = 17`，明显更贵；
- **第 2 组**：两个任务 `key` 都是 `5`（`10-5` 与 `8-3`），按编号输出 `1 2`：`E = max(10, 8 + 5) = 13`；交换也是 13，所以题面固定取小编号在前；
- **第 3 组**：`key` 是 `5, 0, 4` → 顺序 `1 3 2`；`E = max(100, 7+95, 5+98) = 103`。注意 `5 5` 那个任务（`key = 0`）虽然只要 5 点电，但排在最后最省；
- **第 4 组**：只有一个任务，`E = 10^9`，`long long` 也照写不误。

**【样例 2 输入】**

```text
3
5
10 10
10 10
10 10
10 10
10 10
4
3 3
11 5
8 7
10 1
2
1000000000 1
1 1
```

**【样例 2 输出】**（stdout）

```text
50
1 2 3 4 5
16
4 2 3 1
1000000000
1 2
```

**【样例 2 诊断】**（stderr，评测忽略）：无输出

**【说明】**

- **第 1 组**：5 个一模一样（`a = b = 10`）的活，`key` 全 0 → 按编号 `1..5`。`E = 50` 而不是 10：电量**只掉不涨**，做第 5 个活之前已经花掉 40 点，所以开局必须有 50 点（`a_1 = 10`、`a_2 + 10 = 20`、…、`a_5 + 40 = 50`）；
- **第 2 组**：`key = a - b` 依次是 `0, 6, 1, 9` → 顺序 `4 2 3 1`（编号 4 的 `10 - 1 = 9` 最大，最先做；编号 1 的 `3 - 3 = 0` 最小，最后做）。`E = max(10, 11+1, 8+6, 3+14) = 16`。这是本题最容易看错的地方：**排序键是 `a-b`，不是编号、也不是 `a`**；
- **第 3 组**：`key` 是 `999999999` 与 `0` → 任务 1 先做：`E = max(10^9, 1 + 1) = 10^9`，顺序 `1 2`。虽然任务 2 只要 1 点电，但它排在后面时开局仍得攒够 `10^9`。

## 8. 健壮性要求

通用要求见 README 第 4 节，本题额外/重点要求：

- **R1（多组数据）**：一个进程内连续处理 `q` 组；`vector` 每组重新构造，不许把上一组的数据带到下一组（别用全局数组）。
- **R2（非法数据）**：本题输入保证合法（`1 ≤ b_i ≤ a_i`），不需要读入诊断。
- **R3（边界）**：`N = 1`、所有任务完全相同、`a_i = b_i`（`key = 0`）、`a_i = 10^9`、`N = 1000` 且全部 `key` 相同。
- **R4（动态内存）**：用 `vector` 就自动管理；不要手动 `new` 数组又不 `delete`。
- **R8（输出格式）**：两行，第二行编号之间**一个空格**、行末无空格；每组都输出，不要漏最后一组的换行。
- **本题额外要求**：比较函数必须是严格弱序（`cmp(x, y)` 与 `cmp(y, x)` 不能同时为真）；全程 `long long`。

**甲方保证**：`1 ≤ q ≤ 20`；`1 ≤ N ≤ 1000`；`1 ≤ b_i ≤ a_i ≤ 10^9`；同一输入两次运行输出完全一致。**甲方不保证**：`N > 1`；`key` 互不相同；`b_i < a_i`（可能相等）。

## 10. 常见错误

1. **排序键用 `a_i` 升序**：直觉上"门槛低的先做"，但这个例子会打脸：`(10,5)` 与 `(12,2)`，按 `a` 升序做要 17，按 `a-b` 降序只要 12。
2. **排序键用 `b_i` 或 `a_i + b_i`**：都不是本题的键；`key = a_i - b_i` 才让"先做谁、后做谁"的交换不变差。
3. **比较函数写成 `return x.a - x.b <= y.a - y.b;`**：`cmp(x, x)` 返回 `true`，破坏严格弱序，`std::sort` 可能越界崩溃（`-fsanitize=address` 会报 heap-buffer-overflow）。
4. **比较函数里忘了"`key` 相同按编号升序"**：`std::sort` 不稳定，相同 `key` 的先后由实现决定，输出顺序与答案不符 → WA。
5. **用 `int` 存 `pre` 与 `best`**：`N = 1000`、`b_i = 10^9` 时 `pre` 到 `10^12`，`int` 直接溢出成负数，`best` 也跟着错。
6. **`E` 的公式写成"`a_i` 加上总消耗"**：应该用**已经消耗的**前缀和 `pre`，不是总和（总和是浪费）。
7. **`best` 初值写成 0 之外的东西**：`best` 从 0 开始取 `max` 即可（`a_i ≥ 1`，不会有负需求）。
8. **顺序输出用了 0 起的下标**：题面要 1 起编号。
9. **每组之间忘了换行/多打了空行**：两行一组，严格逐字符比对。
10. **用 `cin >> q` 却不检查读到没有**：文件结束时应直接 `return 0`。
11. **自己写冒泡排序**：结果也许对，但规范分要扣（本题考 STL 算法）。
12. **`vector` 下标越界**：`sort` 之后再按编号找原位置容易错位；把 `idx` 一起存进结构体最稳。
