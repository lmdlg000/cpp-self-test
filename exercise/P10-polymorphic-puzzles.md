# P10 · 多态解谜器（虚函数 + 三个小算法）

> 难度：★★★★★　·　对应课件：第 9~10 周（继承、**多态与虚函数**、STL 容器与算法）＋ 第 1~2 周（递归、快速幂、枚举）　·　构建：单文件 OJ（README 第 1.1 节）　·　提交文件：`P10.cpp`
>
> 通用约定（评测命令、输入/输出格式、禁用项、R1~R9、评分）见 [README](README.md)；本文只写本题的额外要求。

## 1. 题目背景

"解谜器"是一个要长期维护的小工具：今天要解三种谜题，明天可能加第四种。朴素写法是一个 `if (type == 1) … else if (type == 2) …` 的大函数，每加一种谜题就要动老代码。这次要用**多态**把它拆开：

- 一个抽象基类 `Puzzle`，只声明"读入数据"和"求解并输出"两件事（纯虚函数），外加**虚析构**；
- 三种谜题各自一个派生类 `FractalPuzzle` / `TilingPuzzle` / `BulbPuzzle`，只实现自己的算法；
- `main` 读入若干查询，按类型 `new` 出对应的派生对象，塞进 `vector<Puzzle*>`，统一用**基类指针**调用 `read` / `solve`，最后统一 `delete`。

三种谜题正好覆盖三类小算法：**快速幂**（分形边长）、**回溯搜索**（三块板拼 4×4）、**枚举 + 递推**（环形灯泡）。

## 3. 必做接口

只需一个 `.cpp`（建议命名 `P10.cpp`）：包含头文件、`Puzzle` 基类与三个派生类、以及题目给定的 `main`。

### 3.1 你要实现的类（签名不得改动）

```cpp
class Puzzle {
public:
    virtual ~Puzzle();                        // 必须虚：main 用基类指针 delete
    virtual void read(istream& in) = 0;       // 纯虚：从输入流读入本题数据
    virtual void solve() const = 0;           // 纯虚：求解并打印答案（不改对象）
};

class FractalPuzzle : public Puzzle {
public:
    FractalPuzzle();
    void read(istream& in);
    void solve() const;
};

class TilingPuzzle : public Puzzle {
public:
    TilingPuzzle();
    void read(istream& in);
    void solve() const;
};

class BulbPuzzle : public Puzzle {
public:
    BulbPuzzle();
    void read(istream& in);
    void solve() const;
};
```

- 三个派生类都要有**可用的默认构造函数**（`main` 里写的是 `new FractalPuzzle()`）；
- `solve()` 是 `const` 成员：算法里的临时数组/容器请定义成局部变量，不要拿成员变量当草稿纸；
- 派生类里存什么数据由你定（`unsigned long long`、`vector<vector<pair<int,int> > >`、`vector<int>` 都行）；
- 允许加私有辅助函数（比如拼板里的 `place()` 递归）。

### 3.2 给定的 `main`（原样粘贴，不得修改）

```cpp
// ---------- 以下 main 由题目给出，不得修改 ----------
int main() {
    int q = 0;
    if (!(cin >> q)) return 0;
    vector<Puzzle*> list;
    for (int t = 0; t < q; ++t) {
        int type = 0;
        cin >> type;
        Puzzle* p = NULL;
        if (type == 1) p = new FractalPuzzle();
        else if (type == 2) p = new TilingPuzzle();
        else p = new BulbPuzzle();
        p->read(cin);
        p->solve();
        list.push_back(p);
    }
    for (size_t i = 0; i < list.size(); ++i) delete list[i];
    return 0;
}
```

`main` 只认识 `Puzzle*`：所有类型分派都发生在 `read` / `solve` 这两个**虚函数**上，以及最后那次 `delete`（走**虚析构**）。**任何对 `main` 的改动（包括多打一个空格）都按 R8 处理。**

## 4. 输入格式

第一行 `q`（`1 ≤ q ≤ 100`，查询个数）。随后 `q` 个查询，每个查询的第一个 token 是类型 `t`：

**`t = 1`（分形）**：后面一个整数 `N`（`1 ≤ N ≤ 10^18`）。

**`t = 2`（拼板）**：后面依次是**三块板**，每块板先是格子数 `k`（`1 ≤ k ≤ 16`），然后是 `k` 组 `(r c)` 表示这块板占用的格子（坐标是整数，可能为负、可能很乱，**同一个格子在描述里只出现一次**；`Σk = 16`）。

**`t = 3`（灯泡）**：后面一个整数 `N`（`3 ≤ N ≤ 200000`），然后是 `N` 个 `0/1`。

token 之间用任意空白分隔（行数不必对应，见 README 第 2 节第 2 条）。

## 5. 输出格式

每个查询输出**一行**（由对应的 `solve()` 打印）：

- `t = 1`：`3^N mod 10007` 的结果（`0..10006` 的整数）；
- `t = 2`：`YES` 或 `NO`（大写）；
- `t = 3`：最少操作次数；若不可能全灭，输出 `NO`。

行末不要多余空格，末尾只有一个换行；不要输出任何提示语。

## 6. 计算规则与约束

### 6.1 分形（`FractalPuzzle`）

1. `A_1` 是 3×3 的方格挖掉正中间那一格；由 `A_i` 生成 `A_{i+1}`：取边长是 `A_i` 三倍的大正方形，切成 3×3 个等大区块，把 8 份 `A_i` 放进除正中间以外的 8 个区块。
2. **边长**的定义：整幅图形外框正方形的边长。`A_1` 的边长是 3，每生成一次乘 3，所以

   ```text
   边长(A_N) = 3^N
   ```

3. 输出 `3^N mod 10007`。`N` 最大到 `10^18`，**必须用快速幂**（每步平方，`O(log N)`），不能写 `for (i = 0; i < N; ++i) r = r * 3 % 10007;`——那要跑 `10^18` 次。
4. 幂运算的数据类型：`N` 用 `unsigned long long`（`10^18` 放得进 `long long`，但 `int` 不行）；`r` 与 `base` 用 `long long`，每次乘完立刻 `% 10007`。

### 6.2 拼板（`TilingPuzzle`）

1. 三块板都由 1×1 方格拼成（每块**连通**），可以对每块做**任意次 90°/180°/270° 旋转**（旋转 `k×90°`）与**平移**，**不许翻转**（不许镜像），也不许把板子拆开或重叠。
2. 问：三块板能否正好铺满一个 4×4 的正方形（16 格，不留空、不越界、不重叠）。
3. 输出 `YES` / `NO`。
4. 提示：把每块板规范化（平移使最小行列坐标为 0、格子排序），求出它最多 4 种不同姿态（正方形/长条可能只有 1~2 种），再从 4×4 的**最左上空格**开始回溯：这个格子必须被某块板的某个姿态覆盖，逐格尝试即可。
5. 面积不是 16 时直接 `NO`。

### 6.3 灯泡（`BulbPuzzle`）

1. `N` 个灯泡围成一圈（编号 `0..N-1`，`i` 的下一个就是 `i+1`，最后一个的下一个是 `0`）。每次操作选定一个位置 `i`，把 `i`、`i+1`、`i+2`（下标模 `N`）三个灯泡的状态**同时取反**。
2. 问：能否通过有限次操作让所有灯泡都变成关闭（`0`）？能的话，**最少**要操作几次。
3. 输出次数或 `NO`。
4. 关键观察：同一个位置操作两次等于没做，所以每个位置要么操作 0 次、要么 1 次，答案就是"被操作的位置个数"。设 `x_i ∈ {0,1}` 表示是否在 `i` 操作，`b_i` 是灯泡 `i` 的初始状态，则对每个 `i` 有

   ```text
   x_i + x_{i-1} + x_{i-2} ≡ b_i  (mod 2)      // 下标模 N
   ```

   一旦确定了 `x_{N-2}` 与 `x_{N-1}`（只有 4 种组合），其余 `x_i` 就能按 `x_i = b_i ^ x_{i-1} ^ x_{i-2}` 依次推出来；四个组合里凡是能让**最后两条方程**也成立的，就是一个可行解，取"1 的个数"最少的那个。找不到可行解就输出 `NO`。
5. 复杂度：每个查询 `O(N)`；`N` 到 `2·10^5`、`q` 到 100，足够。

## 7. 样例

**【样例 1 输入】**

```text
4
1 1
1 10
2 8 0 0 0 1 0 2 0 3 1 0 1 1 1 2 1 3 4 2 0 2 1 2 2 2 3 4 3 0 3 1 3 2 3 3
3 5 0 1 1 0 0
```

**【样例 1 输出】**（stdout）

```text
3
9014
YES
4
```

**【样例 1 诊断】**（stderr，评测忽略）：无输出

**【说明】**

- **第 1 个查询**：`N = 1`，边长就是 3；
- **第 2 个查询**：`3^10 = 59049`，`59049 mod 10007 = 9014`（`5 × 10007 = 50035`）；
- **第 3 个查询**：三块板是"两整行（8 格）+ 一整行（4 格）+ 一整行（4 格）"，直接铺满 → `YES`。注意坐标是从 `(0,0)` 开始的原始坐标，`read` 里要先规范化再求姿态；
- **第 4 个查询**：`N = 5`、状态 `0 1 1 0 0`。围着圈翻三连，最少 4 次能全灭（可以先自己手推：`x = (0,0,1,1,0)` 之类）。

**【样例 2 输入】**

```text
4
1 1000000000000000000
2 12 0 0 0 1 0 2 0 3 1 0 1 1 1 2 1 3 2 0 2 1 2 2 2 3 3 0 0 0 1 1 0 1 0 0
3 4 1 0 0 0
3 3 1 1 1
```

**【样例 2 输出】**（stdout）

```text
3946
NO
3
1
```

**【样例 2 诊断】**（stderr，评测忽略）：无输出

**【说明】**

- **第 1 个查询**：`N = 10^18`，快速幂才能算；答案是 `3946`；
- **第 2 个查询**：`12 + 3 + 1 = 16` 格，三块是"3×4 长方形 + L 形三格 + 单格"。面积够，但 3×4 放进去后剩下一条 1×4 的缝，L 形塞不进去 → `NO`。这就是**面积对 ≠ 能拼**的例子，回溯必须真的搜；
- **第 3 个查询**：`N = 4`、状态 `1 0 0 0`，最少 3 次；
- **第 4 个查询**：`N = 3`、全亮，一次操作（翻转这 3 个）就全灭 → `1`。

## 8. 健壮性要求

通用要求见 README 第 4 节，本题额外/重点要求：

- **R1（多组数据）**：一个进程内连续处理 `q` 个查询，每个查询一个独立对象；不许用全局/`static` 变量存状态（否则第二个查询会看到上一个的残留）。
- **R2（非法数据）**：本题输入保证合法（`Σk = 16`、`N ≥ 3`），不需要读入诊断。
- **R3（边界）**：`N = 1` 的分形、`N = 10^18`、拼板面积不足 16、三块板里有一块只有 1 格、灯泡 `N = 3`/`N = 4`、全亮/全灭（全灭答案是 0）、无解（`NO`）。
- **R4（动态内存 + 虚析构）**：`new` 出来的派生对象必须由 `delete 基类指针` 正确释放——**`~Puzzle()` 不是 `virtual` 就会泄漏**（派生类的 `vector` 缓冲不会被释放）。用 `valgrind --leak-check=full --error-exitcode=1` 或 ASan 自测（R7），要求 **0 errors、0 leaks**。
- **R5（继承 + 多态）**：三个派生类必须**公有继承** `Puzzle` 并**覆盖**两个纯虚函数；漏一个就还是抽象类，`new` 直接编译失败。
- **R8（不改 `main`）**：原样粘贴，一个字符都不改；调试输出只能进 `cerr` 并记得删。
- **本题额外要求**：`solve()` 必须是 `const`（签名固定），算法临时数据放局部；分形必须用快速幂（否则 `N = 10^18` 直接 TLE）。

**甲方保证**：`1 ≤ q ≤ 100`；`1 ≤ N ≤ 10^18`（分形）；每块板 `1 ≤ k ≤ 16` 且三块合计 16 格、各自连通、格子互不重复；`3 ≤ N ≤ 200000`（灯泡）且状态只有 0/1；同一输入两次运行输出完全一致。**甲方不保证**：拼板一定能拼成（会考 `NO`）；灯泡一定有解（会考 `NO`）；坐标已经规范化（可能是负数、可能乱序）。

## 10. 常见错误

1. **忘了 `virtual`**：`void solve() const` 不写 `virtual` 时，通过 `Puzzle*` 调用的是基类版本（纯虚则根本不能实例化）；`read` 同理。
2. **析构没写 `virtual`**：`delete p` 只调 `~Puzzle()`，派生类里 `vector` 的缓冲泄漏；ASan 会报 "allocated in ... leaked"。
3. **纯虚函数写成 `virtual void solve() const {}`**：变成有实现的普通虚函数，`Puzzle` 可以实例化——虽然能跑，但不满足"抽象基类"的要求（规范扣分），也容易在基类里留下错误默认行为。
4. **派生类漏覆盖一个纯虚函数**：`new FractalPuzzle()` 报 "cannot instantiate abstract class"，整题 CE。
5. **`solve()` 里想改成员**：签名是 `const`，赋值就编译错；临时数组放局部（`int g[4][4]`、`vector<int> x(n)`）。
6. **分形用循环乘 `N` 次**：`N = 10^18` 直接 TLE；要用快速幂（平方倍增）。
7. **快速幂里 `int` 溢出**：`base * base` 最大约 `10^8`（`10007^2`）其实放得下 `int`，但 `res * base` 也在这个量级；仍建议 `long long`，别赌。
8. **`N` 用 `int` 读**：`10^18` 读不进去，`N` 变成垃圾值。
9. **拼板忘了旋转**：只按输入姿态搜索，很多 `YES` 会误判成 `NO`；四种姿态都要试。
10. **拼板把旋转写成了镜像**：`(r, c) → (c, r)` 是转置（镜像），不是旋转；正确的是 `(r, c) → (c, −r)` 再平移规范化。
11. **拼板回溯没有"必须覆盖最左上空格"的剪枝**：搜索树爆炸，遇到 `NO` 的用例可能超时。
12. **拼板忘了检查面积**：`Σk ≠ 16` 时还去搜，浪费而且可能越界。
13. **灯泡只枚举了一种起始**：`x_{N-2}`、`x_{N-1}` 有 4 种组合，只试 `(0,0)` 会漏解，`NO` 判错。
14. **灯泡忘了检查最后两条方程**：推完就返回，得到的是"看起来能灭"的假解。
15. **灯泡把"翻转"写成"赋值"**：`b[i] = 0` 而不是 `b[i] ^= 1`，结果全错。
16. **灯泡把一次操作当成翻 3 个而不是模 `N`**：`N = 3`、`N = 4` 时下标会绕回去，必须取模。
17. **`vector<Puzzle*>` 里存了对象而非指针**：`vector<Puzzle>` 会因为抽象类 / 切片（slicing）编译失败或静默丢派生数据。
18. **`delete` 之后还访问指针**：`list` 清空后不要再 `p->solve()`。
19. **在构造函数里读 `cin`**：`read` 才是读入口，构造函数只初始化成员（本题 `read` 是虚函数，构造期间调用也不会绑定到派生版本）。
20. **改动 `main`**：哪怕"只是加个空格"也按 R8 算。
